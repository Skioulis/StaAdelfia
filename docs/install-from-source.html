The code is on GitHub at github.com/Skioulis/StaAdelfia. There are two ways to install it; this page is the first one:

From the source code (this guide)Download the code with git; the server builds the Docker image itself. Updates: git pull and rebuild. Works on x86-64 and ARM servers.
From the ready-made imageNo code on the server, only 3 files; the image comes from Docker Hub (skioulis/gyros-menu). See DEPLOY.md.

Use one of the two per server, not both: they use the same port.

What you end up with: https://<domain>/ is the public menu (guests open it from a QR code), https://<domain>/admin is the owner's page for editing it. Everything the owner enters (the database and the photos) is in one folder on the server, data/.

1What you need

  • A Linux server with Docker Engine and the Docker Compose plugin (docker compose version should work), and git.
  • nginx and certbot on the same server.
  • A domain or subdomain (e.g. menu.example.com) whose DNS record points at the server.
  • Internet access during the build (it downloads the Node.js base image and packages), and about 1 GB of free disk.

You do not need Node.js on the server; everything runs inside Docker.

2Download the code

sudo mkdir -p /srv/gyros-menu
sudo chown "$USER" /srv/gyros-menu
git clone https://github.com/Skioulis/StaAdelfia.git /srv/gyros-menu
cd /srv/gyros-menu

All further commands run in /srv/gyros-menu.

Don't edit the files from git. Only .env, data/ and backup/ are yours; git ignores them, so updates never touch them. Edited code files would block git pull later.

3Create the data folder

The database and the photos go here. The app runs as user id 1000 inside the container and must be able to write to it:

mkdir -p data
sudo chown 1000:1000 data

4Settings and admin password

The settings are in a file called .env. The admin password is never stored, only a hash of it.

A. You received a ready .env file from the owner

Copy it to /srv/gyros-menu/.env and go on to step 5. It already contains the password hash.

That file contains the password hash: keep it private and never commit or upload it.

B. You make the settings yourself

Create .env from the template and build the image once:

cp .env.example .env
docker compose build

Then make the hash. Type the password when asked (at least 10 characters); it is not shown while you type:

docker compose run --rm --no-deps gyros-menu node src/scripts/hash-password.js

It prints a line starting with ADMIN_PASSWORD_HASH='scrypt$…. Open .env and replace the empty ADMIN_PASSWORD_HASH= line with it:

nano .env
  • Keep the single quotes around the hash: it contains $ signs.
  • The username is ADMIN_USERNAME (default admin).
  • Leave SEED_SAMPLE_DATA=false and TRUST_PROXY=1 as they are.
  • NODE_ENV, DATA_DIR, HOST and PORT in .env don't matter: docker-compose.yml sets them.

Give the owner the username and password in person or by phone, not by email.

5Build and start

docker compose up -d --build

The first build takes a few minutes. Then check it:

docker compose ps
curl http://127.0.0.1:8085/healthz

✓ docker compose ps shows the status healthy (within about 30 seconds), and curl prints {"ok":true}.

The app only listens on 127.0.0.1:8085, so nobody outside can reach it until nginx is set up. It starts again by itself after a reboot.

6nginx and HTTPS

The repository has a ready nginx site in deploy/nginx-site.conf. This copies it into nginx with your domain filled in. Replace menu.your-domain.at with the real domain, in both commands:

sed 's/menu.example.com/menu.your-domain.at/g' deploy/nginx-site.conf | sudo tee /etc/nginx/sites-available/gyros-menu > /dev/null
sudo ln -s /etc/nginx/sites-available/gyros-menu /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

Then the HTTPS certificate (certbot also adds the redirect from http to https):

sudo certbot --nginx -d menu.your-domain.at

The site already sets the upload limit for photos (client_max_body_size 6m) and compresses text and the logo for phones.

✓ https://<domain>/ shows the (still empty) menu with the logo, and https://<domain>/admin shows the login page.

The admin login only works over HTTPS. Its cookie is marked Secure, so over plain http the login seems to work but the page jumps straight back to the login form.

7Hand over to the owner

The database starts empty. The owner logs in at https://<domain>/admin; the admin page can be switched between German, English and Greek at the top (DE / EN / ΕΛ).

  1. Categories: create the sections of the menu (e.g. Gyros, Salads, Drinks) in the order they should appear.
  2. Items: add the dishes with name (German required, English and Greek optional), description, price, photo, options such as “large portion +€2”, and the allergens A–R.
  3. Restaurant: name and tagline.

Changes show on the public menu within about a minute.

8QR code for the tables

Make a QR code for https://<domain>/ with any QR generator, or on the server:

sudo apt install qrencode
qrencode -o menu-qr.png -s 12 https://menu.your-domain.at/

Guests see the menu in their phone's language (German, English or Greek). To force one, add ?lang=de, ?lang=en or ?lang=el to the address.

9Backups

Everything to back up is in /srv/gyros-menu/data: menu.db and the uploads/ folder with the photos. This copies the database safely while the app is running:

sudo apt install sqlite3

Then add a nightly job with crontab -e (keeps 30 days of database copies):

30 3 * * * cd /srv/gyros-menu && mkdir -p backup && sqlite3 data/menu.db ".backup backup/menu-$(date +\%F).db" && rsync -a data/uploads/ backup/uploads/ && find backup -name 'menu-*.db' -mtime +30 -delete
Also copy backup/ off the server now and then (another machine or cloud storage). A backup on the same disk doesn't help if the disk fails.

Restore

docker compose down
cp backup/menu-2026-11-26.db data/menu.db      # pick the date you want
rsync -a backup/uploads/ data/uploads/
sudo chown -R 1000:1000 data
docker compose up -d

10Updating to a new version

Make a backup first (step 9), then:

cd /srv/gyros-menu
git pull
docker compose up -d --build
docker image prune -f

Database changes are applied automatically when the app starts. Your .env and data/ are not touched. docker image prune removes the old image to free disk space.

11Going back to an older version

If an update causes a problem, list the versions and go back to the one before:

git log --oneline -10
git checkout <commit>          # e.g. git checkout 239fdf7
docker compose up -d --build

To return to the newest version later:

git checkout main
git pull
docker compose up -d --build
If the older version doesn't start with the newer database, stop it and restore the backup you made before the update (step 9).

13Troubleshooting

ProblemCause and fix
The container stops right awayRun docker compose logs; the message says what's wrong, e.g. ADMIN_PASSWORD_HASH is required in production (step 4).
Cannot use DATA_DIR /data: EACCESThe data folder isn't writable by user id 1000: sudo chown 1000:1000 data.
ADMIN_PASSWORD_HASH is not a valid scrypt hashThe line was cut or the single quotes are missing. Paste the whole line again.
Build fails while downloadingThe server needs internet access to Docker Hub and npm during the build. Try again; check DNS and any firewall.
git pull refuses: “local changes would be overwritten”A code file was edited. git stash (or git checkout -- <file>) and pull again. Put settings in .env only.
port is already allocated (8085)Something else uses the port, e.g. a second install from the Docker Hub guide. Stop it, or change both the port in docker-compose.yml and in the nginx site.
502 Bad Gateway in the browserThe app isn't running (docker compose ps) or nginx points at the wrong port (must be 127.0.0.1:8085).
After logging in, the login form comes backThe site is opened over http instead of https (step 6).
“Too many attempts” at login5 wrong passwords within a minute. Wait one minute.
Photo upload fails (413)client_max_body_size 6m; is missing in the nginx site.
Forgot the admin passwordMake a new hash (step 4 B), replace it in .env, then docker compose up -d.
